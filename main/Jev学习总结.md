# Jev 学习总结

Jev 要解决的是答案空间有限的判断：分类、路由、筛选、打分。证据先写成 state，只放入这次允许使用的字段，标签、未来结果和越权信息留在外面；问题再收成明确的答案空间。是否用 Noul，类别用 Choice，程度用 Score。接口直接返回选项上的概率分布，程序据此执行阈值、路由和动作。开放写作和长链推理仍然留给生成式模型。

读这个分布时，概率、置信度、正确性和校准要分开。只取最大概率会丢掉形状：0.51 对 0.49 与 0.99 对 0.01 选中同一类，把握却完全不同。单条高置信预测仍可能错。校准是群体性质，要在标注样本上对照 NLL、Brier 和 ECE，看报出的概率是否接近实际发生频率。

这些信号进入程序后，由代码负责权限、顺序和副作用。同一份 state 可以一次问出多个候选问题，再按实际分支取用；不确定或代价高的样本转人工、重试或升级。多个维度按业务权重组合，输入则路由到对应处理器，并留下未知类和失败路径。错误代价不对称时，按期望损失选择动作。金额、授权和安全联锁写在代码里。

落到检索时，它适合在已召回的候选上重排、筛选段落、核查引用；最终答案仍由生成模型组织。落到控制时，自然语言先变成判断，设备白名单、动作依赖和执行顺序由程序掌握。复合指令按依赖决定串行或并行，并处理竞态、幂等，以及判断之后状态已经变化的情况。语义上判断为开灯之后，仍要经过授权才能执行。
